# Evaluation system

## Dataset provenance

Phase 6 provides deterministic, synthetic annotations grounded in the repository's
real paper corpus. The annotations were generated by code and have **not** been
human-reviewed. Each retrieval target is an existing chunk ID, while the six
insufficient-evidence cases use unique table markers that the validator confirms do
not occur in the corpus. The seed is fixed at 42 by default.

| Set | Physical rows | Purpose |
|---|---:|---|
| M | 120 | 30 four-turn conversations |
| I | 100 | Balanced five-class intent evaluation |
| R | 100 | Retrieval queries with real ground-truth chunk IDs |
| B | 55 | Guardrails allow/clarify/refuse cases |
| E | 70 | Stratified subset of M for end-to-end evaluation |

E is derived from M and is not counted again when discussing independently authored
evaluation cases. The directory contains 445 physical JSONL rows; M, I, R, and B
contain 375 independently selected/generated cases.

M has the required intent distribution: 42 `new_search`, 40 `follow_up`, 14
`clarification`, 6 `meta`, and 18 `out_of_scope`. Its overlapping annotations contain
46 rewrite turns, 24 second-retrieval turns, 24 refusals (18 out-of-scope plus 6
insufficient-evidence), and 12 cross-paper comparisons. Overlap is intentional.

## Schemas and validation

All rows have a stable ID, non-empty `query`, `synthetic=true`, and
`provenance=synthetic_grounded_in_real_corpus`.

- M additionally records conversation/turn IDs, history, intent, standalone query,
  resolved references, required entities/constraints, retrieval ground truth,
  expected action, and the four overlapping property flags.
- I records the expected intent and any context needed to make the sample independent
  of evaluation order.
- R records one or more real `ground_truth_chunk_ids`.
- B records `expected_action` (`allow`, `clarify`, or `refuse`).
- E records `source_turn_id`; every evaluation-relevant field must exactly match M.

The validator checks exact sizes/distributions, 30×4 dialogue structure, field types,
unique IDs, E⊂M content equality, corpus reference integrity, comparison cardinality,
refusal consistency, and absence of each insufficient-evidence marker from the corpus.

## Metric definitions

- **Intent Accuracy:** exact five-class matches divided by successfully evaluated I
  rows. A gold-by-prediction confusion matrix is emitted.
- **Query rewrite accuracy:** a row passes only when its normalized rewrite retains
  every annotated entity, resolved reference, and constraint. It is not full-string
  equality; per-sample missing items are saved.
- **Recall@K:** query-level hit recall. A query is a hit when at least one ground-truth
  chunk occurs in the first K results. Reported for K=1, 5, and 10 separately for
  dense, hybrid, and hybrid+rerank.
- **Guardrails accuracy:** exact equality of expected and predicted
  allow/clarify/refuse actions.
- **Reflect refusal accuracy:** exact refusal-decision accuracy on the annotated
  second-retrieval/insufficient-evidence subset, separately with the second-retrieval
  budget set to zero and one.
- **Citation validity:** non-duplicate predicted citation occurrences that belong to
  final evidence divided by all predicted citation occurrences. Duplicate occurrences
  remain in the denominator.
- **Citation precision/recall:** unique correct predicted citations divided by all
  predicted occurrences / all ground-truth citations respectively.
- **Pipeline Success Rate:** the conjunction of correct routing, retrieval, expected
  answer/refusal action, and citation behavior. All four components must be true.
- **Memory consistency:** fraction of required entities, constraints, comparison
  targets, paper identifiers, and citations retained after each turn, reported for
  `off`, `on`, and `compressed`.
- **Token overhead:** average input/output/total Provider tokens and serialized memory
  context length per mode, plus total-token delta and ratio versus `off`.

Every metric reports `evaluated`, `failed`, `skipped`, and `unevaluable` counts. Failed
or skipped rows are never silently added to a metric denominator. Retrieval rows with
empty ground truth are explicitly `unevaluable`.

## Commands

Build and validate annotations without an API key or index models:

```bash
conda run -n nanocc python -m eval.run_evaluation \
  --suite datasets --build-datasets --seed 42
conda run -n nanocc python -m eval.validate_datasets \
  --data-dir eval/data --chunks corpus/chunks.jsonl
```

Run the local retrieval ablation:

```bash
conda run -n nanocc python -m eval.run_evaluation \
  --suite retrieval --device cpu --seed 42 \
  --output-dir eval/results/retrieval
```

Run Provider-dependent component/E2E/Reflect/Memory evaluations after exporting the
matching API key:

```bash
conda run -n nanocc python -m eval.run_evaluation \
  --suite provider --model deepseek-v4-flash --device cpu --seed 42 \
  --output-dir eval/results/provider
```

Use `--suite all` for a complete Phase 7 run. Provider suites fail before making model
calls when the selected provider has no configured key.

Each run writes `per_sample.jsonl`, `summary.json`, `summary.csv`, `summary.md`, and
`run_config.json`. The run configuration records model/provider, seed, Python/platform,
portable retrieval settings, full index manifest, dataset statistics, and provenance.

## Current limitation

Phase 6 validates the system and annotations but does not publish formal percentages.
The synthetic annotations require human review before they can be described as
human-labelled, and the full Provider-backed experiments belong to Phase 7.
